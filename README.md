## 工作边界

- 本次账号和当前客户端优先。根目录旧账号 JSON、历史账号报告不能证明当前持有资产。
- 星级取精确武将 ID 且自带战法一致的 `hero.json.quality`；`hero_extra.quality=4-SR` 不是四星。不按姓名、众数或库顺序锁版本。
- 战法默认按可分配总份数重组；明确保留的旧队继续占用。导出只有空闲数，资料库补出的总份数必须注明推定来源。
- `XP` 是标签；新获取须按 `acquisition_stage` 和 `acquisition_stage_status` 过门禁。已有可用与可新获取分开判断。
- 先验收阵容，再补两套施政；`lineup_ready` 与 `delivery_ready` 分开。未知赛季、战法参数、研究进度、宝物或副卡数不补猜。
- 摘要战报只统计结果。随机性或强度调整须每队至少 5 份含事件证据的代表战报；完整事件链加当前文本确认的确定性硬错误可立即修正。
- 图像结论须按项目规则调用 `vision_glm.py` 并交叉核验；本机该链路尚未恢复和验证。不能凭猜图代替，也不能据接手请求自动发起付费调用。
- 原视频、静帧与中间材料曾按历史验收退役；旧 `evidence_chain` 仅作历史来源记录。重定位路径不能恢复已退役内容。
- 不直接运行旧删除、归置、打包或全量重渲脚本。具体生产任务启动前须检查输入、输出范围与现存材料。
