# 率土之滨配将 Agent

> 一个面向《率土之滨》的账号诊断、配将规划、资源校验、交付验收和战报复盘项目。
> 项目重点不是生成“万能阵容答案”，而是把当前账号事实、官方资料边界、攻略案例、战法资源和实战证据串成可复核的决策链。

## 项目简介

本项目最初用于对抖音攻略视频做逐帧蒸馏，后来逐步扩展为完整的配将 Agent 工作库：

- 从视频、音频、静帧和字幕中提取可迁移知识；
- 把案例整理为条件、触发、职责、资源成本和失败边界；
- 建立武将、战法、宝物、赛季阶段和名称白名单；
- 从当前账号导出中解析唯一武将版本和战法份数；
- 按前三主力优先、全局资源核算的方式生成候选阵容；
- 检查 COST、站位、距离、兵种、觉醒、赛季门禁和效果冲突；
- 用结构化战报反查最早异常事件，形成“战报 → 问题 → 改队 → 再验收”闭环；
- 将案例知识、规则、审计和成品报告整理为可持续检索的资料库。

本项目是证据有界的决策辅助工具，不替代当前客户端、当前账号截图、当前战法文本和真实战报。程序通过只证明结构规则通过，不证明阵容强度、胜率或当前环境排名。

## 核心功能

### 1. 当前账号解析

[`parse_account.py`](工具/配将服务/parse_account.py) 读取百家社原始导出，完成以下检查：

- 按内部 ID 区分武将；
- 用自带战法 ID 锁定同名版本；
- 读取战法空闲份数；
- 从本地资料库标注总份数来源；
- 分离未解决武将、侍卫和非可配记录；
- 标记宝物、研究进度等导出未提供字段。

原始账号导出不进入仓库。只读解析优先，只有用户明确要求时才生成脱敏账号档案。

### 2. 阵容规划和全局资源核算

配将默认流程：

1. 先确认赛季、剧本、用途、队伍数、单队 COST、觉醒资源和保留旧队；
2. 先列候选，不提前承诺战法占用；
3. 按优先级分配前三主力；
4. 再安排第 4 队以后和工具队；
5. 按战法总份数核算交换，不只按当前空闲数计算；
6. 检查距离、速度、兵种、阵营、冲突、触发顺序和效果冗余；
7. 阵容通过后再补“金币获取”和“自由建议”两套施政；
8. 最后用代表战报验证。

### 3. 结构校验与交付门禁

- [`season_gate.py`](工具/配将服务/season_gate.py)：区分已拥有和当前可新获取。
- [`validate_lineup.py`](工具/配将服务/validate_lineup.py)：检查武将所有权、战法份数、COST、站位、距离、兵种、觉醒和资源冲突。
- [`audit_consultation.py`](工具/配将服务/audit_consultation.py)：检查正式交付字段、警告处理、施政正文、未上队五星原因和报告生成。
- [`analyze_battle_reports.py`](工具/配将服务/analyze_battle_reports.py)：区分摘要战报和事件战报，统计代表样本，辅助识别重复机制问题。

验收状态分为：

- `lineup_ready`：阵容和字段达到继续制作施政的条件；
- `delivery_ready`：阵容、施政、警告复核和交付字段均合格。

两个状态都不等于强度已经证明。

### 4. 战报反馈闭环

战报分析先读准备回合、行动顺序、首次控制、首次增益、主伤害源和首次异常，不先看总伤害和武勋。

- 完整事件链与当前文本确认的确定性硬错误，可立即修正；
- 概率、目标选择或一般强度问题，每队至少 5 份含事件证据的代表战报；
- `summary_only` 只统计结果，不进入机制诊断；
- 单场胜负不能直接改队；
- 调整时只改一个主要变量，再重新验收和复测。

### 5. 攻略知识检索

报告不是模板库。检索报告时，优先读取以下字段：

- 这套队成立需要哪些事件；
- 谁供触发、谁接伤、谁保护、谁恢复、谁收口；
- 哪个核心将法不能替代；
- 替换后会损失什么；
- 战法冲突和同效果覆盖在哪里；
- 资源不足时先砍哪一队；
- 哪些结论只是历史样本或作者观点。

## 安全与证据边界

- 不提交、打印或公开百家社原始账号导出、Token、Cookie、API Key 或私密路径；
- 不按姓名、库顺序或众数推断同名武将版本；
- 不把 `hero_extra.quality=4-SR` 当成四星；
- 不把 XP 标签直接当征服赛季；
- 不把空闲战法数当成总份数；
- 不把程序检查通过当成强度或胜率证明；
- 不把历史报告、单场胜报或作者排名当成当前环境答案；
- 不把已退役源路径缺失解释成文件仍可恢复。

更完整的接手约束见 [AGENTS.md](AGENTS.md) 和[口径与执行边界](资料库/策略知识库/迁移方法学习_20261012/口径与执行边界.md)。

## GitHub 附件策略

主仓库只保留代码、规则、结构化 JSON、索引和学习报告，普通克隆约 18 MB。

不进入普通克隆的内容：

- 1.10 GB 便携 LibreOffice；
- 临时渲染稿；
- 原始视频、图片、PDF 和压缩包；
- 本地缓存与敏感账号导出。

可选的原始来源附件位于：

[source-attachments-v1](https://github.com/304939905/ShuaiTuZhiBing-PeiJiang-AGENT/releases/tag/source-attachments-v1)

附件包包含部分长期网页、原始马岱视频、抽帧和压缩包，不是全部 105 个来源视频。是否下载不影响代码、规则、JSON 和最终报告使用。
