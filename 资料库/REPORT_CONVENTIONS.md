# 率土之滨深度学习报告 · 固定规则手册

> 本文件是「抖音攻略视频逐帧深度学习」项目所有报告生成/复核的**单一事实来源（single source of truth）**。
> 与 `FRAME_AGENT_BRIEF.md`（子智能体作业书）、`frame_report_schema.md`（JSON 结构）、各 `gen_*.py`（渲染器）配套使用。
> 任何文案/格式修正都改母本（`.py` / `frame_json`），不要只改 docx。

---

## 0. 四大硬标准（每份报告必含）

1. **报告索引块**（标题后、正文前）：关键词 + 核心武将（版本） + 报告生成日期 + 报告路径；并追加进 `reports_index.md` 主索引。
2. **武将版本标签**：固定格式 + 固定出现位置（见规则 1）。
3. **报告生成日期**：唯一时间戳，中性字段，**禁止写任何时效性警告语**（"可能已过时/以官方更新为准"等）。
4. **AI 主动推断独立成章**：明确标注"非视频原话"，与视频事实物理隔离（见规则 4）。

## 1. 武将版本标签：格式 + 出现位置

### 1.1 格式（名字绝不内嵌）
- 正确：`阵营-兵种-星级`，例：`群-骑-5星`、`群-步-5星`、`蜀-步-5星(SP)`。
- **错误（严禁）**：`群-木鹿大王-骑-5星`、`群-兀突骨-步-5星` —— 名字已在标签外写出，标签内只填 阵营-兵种-星级。
- SP 版：末位加 `(SP)`，如 `蜀-步-5星(SP)`。
- **判定主键 = 自带战法**：用画面武将的自带战法反查 `hero_extra.json` 的 `methodName` 确定 阵营/兵种/星级/SP，禁止凭记忆手写。覆盖不到则 WebSearch 核验（优先网易大神 ds.163.com）。

### 1.2 出现位置（避免冗余，关键）
- 版本标签**只出现在两处**：
  1. 报告开头「核心武将（版本）」清单（平铺所有提及武将）；
  2. 阵容表格的「武将」列（逐投稿对照参考结构）。
- **正文 prose（结论/讲解/点评/作者建议/AI 推断段）一律只写武将名，不重复版本标签**，**除非重名**（普通版 vs SP 版同名，如张飞/关银屏，此时正文用「张飞(SP)」区分）。
- 开头清单 + 表格列已提供版本，正文无需再写。
- **禁止单独生成「武将版本对照表」节**：该节与开头「核心武将（版本）」清单完全重复（同一批武将、仅列 `武将|版本标签` 两列、无任何额外信息），属纯冗余。2026-08-20 已删除 009/013 两份的该节，并修 `gen_refined_report.py`（旧56项目渲染器）与 `gen_refined_report_zhenrong.py`（阵容新批渲染器）模板，未来重渲不再生成此节。

## 2. 位置（站位）规则

- **位置由阵容排序承载**：一份阵容按「大营 / 中军 / 前锋」顺序列出武将（第一行=大营、第二=中军、第三=前锋），位置从排序即可读出。
- **位置词（中军/前排/前锋/大营）严禁并入武将名**：
  - 正确：`群-步-5星`（兀突骨标识）、正文中"兀突骨"；
  - 错误：`中军兀突骨`、`前排董卓`、`大营祝融`。
- **武将资料里的推荐站位 = 系统建议，并非强制**：某将可放在任意位置。例：作者建议"把大营位的祝融替换为兀突骨"，即**兀突骨接大营位**（兀突骨并非固定中军）。
- **替换/替代表述固定写法**：`用 X 替换大营位置的 Y 抓法刀`
  - X 不带版本、不带位置；「大营位置的」只作**目标槽位限定**。
  - 不要写 `用中军位的 X 替换大营位的 Y`（易误解 X 固定中军）。

## 3. 宝物/战法核验（distance 机制）

- 攻击距离字段在 `hero_extra.json` 的 `distance`。
- 钜黍效果含「攻击距离+1」。
- 例：祝融 `distance=3` → 需钜黍+1 补足至 4（大营菜刀常见）；吕布 `distance=4`（长弓版）已满足，**不需钜黍**。
- **反查主键用自带战法**；典藏战法补 `official_jineng_supplement.json` 白名单消误报。

## 4. AI 主动推断（独立成章，鼓励但须可溯源）

- 凡 AI 对游戏机制的**主动推断、延伸建议、下位替代、宝物/站位判断**，**严禁混写进视频事实部分**（核心结论/体系讲解/阵容点评/作者建议）。
- JSON 顶层 `ai_inference` 字段（数组），渲染为单独章节，标题例：「六、AI 智能体主动推断内容（非视频原话，供参考）」。
- 每项：`{point, evidence, confidence}`，evidence 须含本地库字段 + 网易大神链接 + 画面时间点。
- **推断前强制核验（杜绝盲推）**：涉及"某将带某宝物/某将替代某将/某将站位"必须先查 `distance/type/quality` + 网易大神，把证据写进 `evidence`。**禁止凭通用原理或记忆盲推。**
- **真实翻车案例（攻其篇）**，均因未查 `distance`/画面站位即下结论：
  1. 误推"吕布大营首选钜黍" → 实际吕布 `distance=4` 已满足、不需钜黍（仅祝融需）。
  2. 误推"凑不齐曹操用兀突骨当前排" → 曹操从未在视频出场；且把武将推荐站位当固定约束（兀突骨可放大营，位置非强制）。

## 5. 工程化与交付（防复发）

- **用户真实桌面 = `D:\Desktop`**（项目根 `D:\Desktop\shandou`）。**不是** `C:\Users\Administrator\Desktop`（另一账户目录，用户看不到）。交付文件一律放 `D:\Desktop`。
- **改报告必须改生成器母本，不能只覆盖 docx**：docx 由 `gen_*.py` 渲染，只手改 docx 下次重渲会复发旧错。
- **渲染须注入 PYTHONPATH**：`PYTHONPATH="D:/WorkBuddyData/python-env/shandou/Lib/site-packages" <managed-python> <script>.py`，否则 `No module named 'docx'`。
- **自检必须覆盖表格单元格**：`document.paragraphs` **不含表格内容**，须遍历 `document.tables` 单元格。只扫段落会漏掉表格里的错误字符串（"钜黍（吕布）"曾藏在投稿三表格 takeaway 单元格，段落自检误判为干净）。
- **多份副本同步**：渲染产物同步到 学习汇报/、学习成果汇总/<批次>/、D:\Desktop 三处，保持字节一致。
