## 硬性规则

1. `file` 必须是 `抖音_frames_dense_1s/<frames_dir>/` 下**真实存在**的文件名，
   命名格式 `frame_%04d_MM-SS.jpg`，序号从 0 开始（frame_0000_00-00.jpg = 第 0 秒）。
   写之前先 `ls` 确认，写错会在报告里渲染成红色「图缺失」。
2. `ts` 必须与 `file` 中的时间一致。
3. 判断不了的内容写进 `limitations`，**绝不编造**。画面看不清就说看不清。
4. 中文引号统一用「」，不要用 " " 或 “ ”，避免 JSON 转义出错。
5. `timeline` 全部帧合计控制在 20~40 张（报告篇幅与信息密度的平衡点）。
6. **武将书写与位置（详见 FRAME_AGENT_BRIEF.md 第 2 条）**：版本标签只写 `阵营-兵种-星级`（名字绝不内嵌，如写 `群-步-5星` 而非 `群-兀突骨-步-5星`）；标签只出现在开头「核心武将（版本）」清单与表格武将列，正文 prose 一律只写武将名（除非重名）；位置由阵容「大营/中军/前锋」排序承载、且非武将固有属性（武将资料推荐站位只是系统建议，可放任意位置）；替换表述固定为「用 X 替换大营位置的 Y」。

# 阵容新批专用的 entities 结构（2026-08-21 补充）

旧 schema 不含 entities（只适合逐帧报告）。阵容视频需要按"队伍/武将"结构化字段，补充在 entities 顶层键下。**4 色框版字段映射**：

| 画面色框 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 🔴 红框（宝物名） | `gear` | `string \| null` | **宝物图标右侧大字**。无宝物=空槽 → `gear=null`，**禁止编造默认宝物** |
| 🟢 绿框（宝物词条） | `traits` | `string[]` | **宝物名正上方小字**。不一定有，无 → `traits=[]`。**⚠️ 2026-08-21 用户规则：识别结果仅做参考，置信度低，不精细化处理**（此字段不做逐字核验/交叉核验，宁缺勿错） |
| 🔵 蓝框（兵种词条） | `unit_traits` | `string[]` | **宝物栏下方/武将卡旁小字**。不一定有但通常有，无 → `unit_traits=[]` |
| 🟡 黄框（无宝物空槽） | `gear=null` | — | 仅武将没带宝物时显示，**黄框不存字段** |

**JSON 结构示例**：
```jsonc
"entities": {
  "teams": [
    {
      "name": "神赏法刀",
      "slot": 1,
      "positions": [
        {
          "pos": "大营",
          "hero": "王异",
          "skills": ["世仇", "众谋不懈", "文伐"],
          "gear": "元戎",        // 🔴 红框
          "traits": ["选锋"],    // 🟢 绿框
          "unit_traits": ["地利", "齐射"]  // 🔵 蓝框
        },
        {
          "pos": "中军",
          "hero": "卫瓘",
          "skills": ["持节镇西", "神兵天降", "大赏三军"],
          "gear": null,          // 🟡 黄框（空槽）
          "traits": [],          // 无绿框
          "unit_traits": ["守备", "勇毅"]  // 🔵 蓝框仍独立显示
        }
      ]
    }
  ]
}
```

**铁律**（与 FRAME_AGENT_BRIEF_ZHENRONG.md 同步）：
1. 三层独立**不一定齐全**——没有就写空，不要拿兵种词条当宝物名
2. **不臆造默认宝物**——空槽就 `gear=null`，禁止写"未装备"等
3. 每个名字必须从对应色框逐字转录，禁止跨框猜测或合并相邻词
4. 与官方库（hero_extra / official_gear_names / gear_id）核对，官方库无的词条写 limitations 标注
