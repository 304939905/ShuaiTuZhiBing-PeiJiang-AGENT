## 二、冲突清单（按严重程度排序）

### ✅ C1 ｜ 公式数值冲突 —— 大赏三军簇（神兵天降 / 避其锋芒 / 无心恋战同簇）【已结案】
**这是最关键的冲突，直接影响所有增伤/减伤战法的数值计算。**

| 来源 | 表述 |
|---|---|
| 阈值表 image_0 + image_5 公式备忘录 | `最终数值 = 基础30.0% + 0.150% × (对应属性 − 80)`，四舍五入取整 |
| 视频1 旁白（00:28–01:22） | 「神兵大赏比起无心的通用公式：**20 + 属性 × 0.145**」 |

**量化对比（以谋略 176 为例）：**
- 按阈值表：`30 + 0.15 × (176−80) = 30 + 14.4 = 44.4 → 44%`
- 按视频1：`20 + 0.145 × 176 = 20 + 25.52 = 45.52 → 46%`
- 绝对差约 **2%**，且两公式仅在属性≈400 时才重合（实际不可能），属**结构性不一致**。

**佐证倾向（非裁决）：**
- ✅ image_5 备忘录原文明确写「（对应属性−80）×增长率 + 基础数值」，与阈值表一致。
- ✅ 视频2 称「大赏/神兵一般 **6-7 点谋略跳一档**」：growth=0.15 时每 +6.67 点属性结果 +1%，与「6-7 点一跳」吻合；视频1 的 0.145 也≈7 点/1%，步长规律不矛盾，但**绝对常数**矛盾。
- ⚠️ 视频1 的「二十 / 零点一四五」疑似口误或简化（与「三十 / 零点一五」仅一字之差，语音易混）。

**建议**：默认以**阈值表（基础30 / 增长0.15 / 减80）**为准录入，但请你在游戏内或官方渠道确认该簇真实公式后再定稿。

**✅ 用户确认结案（2026-08-20）**：公式 `基础30% + 0.15%×(谋略−80)` **正确**。视频1 旁白的「20 + 0.145×属性」为口误/简化，不予采纳。视频 00:16 显示吕蒙发动后「伤害提高 80%」属**特例**（具体原因未知，疑为高红度特例或叠加展示），不代表公式错误。故以阈值表公式为准正式定稿。

### ✅ C2 ｜ 同名异效 —— 徽言龙凤【已结案】
| 来源 | 效果 / 属性 / 基础 / 增长率 |

| image_0 增伤类 | 我方增伤 / 谋略 / 7.0% / **无数据** |
| image_4 其他数值类 | 士气提升 / 谋略 / 10 / 0.05 |

**问题**：同一战法在两表出现**两种不同效果**（增伤 vs 士气提升）。
- 可能 A：该战法本就是多效战法（同时增伤 + 提升士气），两表各记其一，合法。
- 可能 B：其中一表录入有误。
- 额外障碍：image_0 增长率标「待数据」，**无法用公式算出增伤幅度**。

**待确认**：徽言龙凤是否为多效战法？image_0 的 7.0% 增长率缺失值是多少？

**✅ 2026-08-20 用户授权 + 本地官方战法库交叉验证结案**：

1. **多效战法确认** ✅：官方战法库 `hero_extra.json` 司马徽（id 100811, methodId 200294）描述：
   > 「友军全体共计造成6次伤害后，使友军全体获得以下效果：**士气提升10.0（受谋略属性影响）**；**每回合行动时造成的所有伤害提升7.0%（受谋略属性影响），可叠加**；每回合行动时有60.0%的几率对随机敌军单体造成1次攻击伤害（伤害率150.0%）或策略攻击伤害（伤害率120.0%，受谋略属性影响），由攻击或谋略属性中较高的属性决定」

   即同一条描述同时给出「士气提升」+「所有伤害提升」+「概率攻击」**三效并存**。两表各记其一，**均为合法多效分项**。

2. **基础值核对**：
   - 增伤 7.0% → 与官方"造成的所有伤害提升7.0%"一致 ✅
   - 士气 10 → 与官方"士气提升10.0"一致 ✅

3. **增长率核对**：
   - 增伤增长率：image_0 原标"待数据"，**官方描述未给具体增长率数值**（仅"受谋略属性影响"），按用户指示"没找到确切数据就写无数据" → **改为「无数据」**
   - 士气增长率：image_4 记 0.05，官方描述亦未给具体增长率数值。表格图提供 0.05 作为**参考值**保留（属玩家民间整理），但无官方确认。

**结论**：多效战法 ✅ 跨表合法；增长率数据状态如上。

### ✅ C4 ｜ 数据不可计算 —— 遗志【已结案 + 机制明确 + 9999% 含义确认】
| 来源 | 效果 / 主属性 / 基础 / 增长率 |
|---|---|
| image_2 恢复类 | 单体回血 / —（不受属性影响） / **9999%** / —（无增长率） |

**问题**：基础 9999% 与空白主属性/增长率疑似**占位符**，说明该战法回血机制**不按通用线性公式**，门槛逻辑特殊（疑为按损失兵力/特定条件触发，而非纯属性阈值）。

**处理**：已标记，未纳入速查公式计算；建议另查该战法独立说明。

**✅ 2026-08-20 用户确认 + 本地官方战法库交叉验证结案**：

1. **9999% 含义确认（用户人工确认）**：**9999% = 回复至满血**。回满血无法用有限百分比表示，故表格以 9999% 占位编码；**无增长率是正确字段**——遗志回血不受属性影响。**非数据源错误**。

2. **官方机制确认**（`hero_extra.json` 孙坚 id=100033, methodId=200033，也在 `jineng_list.json` 通用战法 200033）：
   > 「战斗开始后第3回合，使我军前锋步兵或弓兵恢复极大量兵力，此后，受到普通攻击可以进行反击（伤害率85.0%），**同时无法恢复兵力**，持续直到战斗结束」

3. **机制定性**：
   - **触发时机**：战斗开始后第 3 回合（**固定回合触发**，非属性阈值）
   - **效果 A**：使我军前锋（步兵或弓兵）**恢复至满血**（官方"恢复极大量兵力"= 回满血）
   - **效果 B**：此后受到普通攻击可反击（伤害率 85%）
   - **限制**：同时无法恢复兵力，持续直到战斗结束
   - **增长率**：无（不受属性影响）——这与表格「主属性/增长率空白」完全自洽

**结论**：遗志为**回合触发型机制战法**，不按属性阈值公式建模；`threshold_db.json` 中标 `full_heal_encoded`（回满血编码，非错误），机制按官方描述记录，**不纳入线性公式计算**。
