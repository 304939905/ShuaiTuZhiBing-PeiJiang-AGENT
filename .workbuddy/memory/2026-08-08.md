## 2. 关键排错经验（重要，避免重复踩坑）

### 坑 A：核验方法本身会制造假故障
最初用「缩放到 64×36 灰度 + 随机 seek 回读」比对，得出 MAE 3~19、抽样只过 3/10，一度误判抽帧出错。
根因两条：① 缩放插值放大差异，把 MAE 基线抬高；② `cv2.CAP_PROP_POS_FRAMES` 随机 seek 在 H.264 上不精确，且结果依赖解码器当前位置，同一帧号两次 seek 结果可能不同。
**正确做法：全分辨率 + 顺序解码做 ground truth**，MAE 立刻降到 0.5~1.3，偏移归零。
教训：核验出异常时，先证伪"核验方法本身"，再怀疑被核验对象。

### 坑 B：偏移 -1/-2 帧不是错误
少数帧报偏移 -1/-2，实测其 MAE 仅 0.25~0.34。深挖发现源视频存在**完全重复帧**（相邻帧 MAE = 0.0 / 0.001 / 0.02），且 fps 为 29.993 非精确 30。重复帧使"最佳匹配位置"存在歧义，argmin 落在哪帧都对，画面内容并无错误。

### 坑 C：管道 + 中文输出导致 exit 1 无任何输出
`python xxx.py | tail` 在中文 print 时会静默失败（exit 1、无 stdout/stderr）。
**解决：加 `PYTHONIOENCODING=utf-8` 并重定向到 .log 文件再 cat**，不要直接管道。

### 坑 D：顺序解码要流式，不能全量缓存
缓存 90 秒 ×1902×1080×3 ≈ 16 GB 直接 OOM（进程 exit 1 无输出）。
**解决：流式读取，只保留 target±3 帧**。样本量 ≤8 个视频/次较稳。

### 坑 E：Bash `rm` 在中文路径下删除失败
safe-delete 会报 `relative path rejected (must be absolute)` 与 `SAFE_DELETE_FAIL_CLOSED`，**文件实际未被删除**。需改用 Python 删除或直接保留。
