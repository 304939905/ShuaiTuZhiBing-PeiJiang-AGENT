# 规则 01：武将卡卡面识别

> 权威来源：用户 2026-08-22 讲解（标注图 `D:\Desktop\11\frame_000013_00h00m12s000ms标注版.jpg`）
> 背景：源视频清晰度有限，密集卡面逐卡识别吃力（此前多次误读）——只取能锁定位的字段，模糊不硬猜。

## 卡面五要素（从左到右/从上到下）

1. **左上角**：阵营-武将名（例：`群-华雄`）→ 阵营+名字。
2. **星级区**（武将名右侧）：共 5 颗星；**星级=总星数**（4 星=4 颗橙星，5 星=5 颗橙星），**红度=红星数**（全黄=0红，1红星+4黄星=1红，2红星=2红…）。⚠️ **「极」是红度满级标识（最高红度），不是第 6 颗星**：4 星武将满红度也带「极」红标，应记作「4星极」而非「5星」。曾把「极」误当第5星导致 4 星错升 5 星。
3. **觉醒标志**（星级右侧）：有图标/标志=已觉醒（开启第三格战法槽）；无=未觉醒。
4. **特殊版本标志**（白框/卡面右上）：`SP`/`XP` 标=特殊版本武将（对照官方库 groupName/season 字段）。
5. **黄框三信息**（从左到右）：**等级-统率值-兵种和攻击距离**（例：40级-3.5-骑兵-攻击距离2）。

## 日常表述规则（锁定武将的唯一写法）

- 常规写法：`阵营-武将名-星级-兵种`，例 `魏-曹操-5星-骑`。**此写法唯一锁定武将，绝不产生歧义**。
- **红度/统率值/攻击距离/觉醒 不写入日常表述**——仅在配将思考（红度门槛/cost 限制/攻击距离补足）时需要，按需查本地库或标注。
- 画面转录：能读出星级就读（如 5星），读不出写 `?`；**禁止用 cost/红度数字冒充星级**（曾把"4红"误读成"4星"）。

## 判读输出要求

- entities.teams.positions：hero 只写武将名；**版本优先按已确认的自带战法 → method_map[战法] 锁定**。看不到自带战法时，可用同一清晰帧的「阵营 + 总星数 + SP/XP/无标识」反查官方库；三项不足、候选不唯一或无原帧路径时必须写“版本待核实”。`hero_star_fixed.json` 的众数仅可辅助检索，绝不可单独决定同名多版本。卡面证据须写入 `version_visual_evidence.json`（旧批）或对应 JSON 实体字段（新批）。
- timeline/visual_only 画面描述：按五要素记录，写 `武将(星级 N红 Lv.X)` 即可，不写 cost；觉醒/SP/XP 有则标注。**星级必须与画面一致，禁止写固化表众数星级**。

## 武将库列表 / 筛选条件铁律（2026-08-25 用户定案）

- **“画面出现若干武将”不等于“当前按某类筛选”。** 只有筛选面板已展开且“星级 / 性别 / 阵营”等条件文字与选中状态在同一帧清晰可见，才可写“4星库”“女将筛选”“吴阵营筛选”等。
- 右侧仅有“筛选”按钮、未展开的筛选面板，或只看到一组女将卡，均只能写“武将列表”“可见武将含……”；**禁止据此补写筛选条件**。
- **列表中单张卡的星级必须逐卡锚定。** 不能因本地库存在某武将的4星版本，就把同名卡或整页列表写成4星；画面星标不清时，必须写“星级未能确认”，不得以名字、性别、阵营或卡池页外观替代。
- 多帧滚动列表必须按 `ts` 分开记录；**禁止把00:20的列表与00:25的列表拼接成一条“该页展示……”描述**。若需要汇总，必须写明时间范围，并只保留各帧共同可见的信息。
- 例：`00:25 可见吴·小乔、吴·大乔、汉·貂蝉等女性武将；筛选条件和各卡星级未显示清楚。` 合格。`4星女将库展示……` 在未见筛选UI时不合格。

- 视觉模型结论 + 资料库交叉验证（战法→method_map）一致方可落库；两者冲突时以画面事实（即用户肉眼）为准。
- ⚠️ **视觉模型对星级判读可能误红度**：不能只凭模型一句“5星”落库。若无自带战法，须在同帧逐项确认阵营、总星数和 SP/XP/无标识，并让本地官方库得到唯一候选；缺一项即“版本待核实”。画面与自带战法冲突时保留原帧、重新核验，不猜测。
