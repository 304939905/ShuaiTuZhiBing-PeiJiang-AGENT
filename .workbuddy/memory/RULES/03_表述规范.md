# 规则 03：表述规范（报告与 JSON，防歧义/防冗余）

> 权威来源：用户审阅迭代（2026-08-21/22）

## 制作总标准（2026-08-22 起，最高优先级）

- **唯一制作标准 = AI 阅读 / 使用 / 理解**。报告与 JSON 一切以机器消费为准（检索、问答、建库、跨文档对齐）；人类浏览舒适度为次级目标。
- **冗余即删**：任何已在结构化字段（核心结论 / 画面要点 / 时间线 / 来源索引）完整覆盖的信息，禁止再用散文段落复述。重复 = 噪音，且会带来前后不一致风险。
- **空章节不渲染**：无内容的章节（术语 / AI 推断等）直接跳过，不留空壳标题（生成器已 `if glossary` / `if ai` 守卫）。
- **来源/局限/索引项不得留下空白标签**（2026-08-25 用户规则）：若绝对路径、敏感信息或不可信原信息不能进入成品，必须把该项改写为可读的证据说明；若因不可信而删除原信息，必须在原位置明确写出“未采纳/删除的原因和证据边界”。禁止仅保留“官方白名单核验：”“OCR 误读映射：”等空标签，也禁止静默删空。
- 散文「摘要(one_line)」已于 2026-08-22 从报告删除："一、内容摘要" 改名 "一、核心结论与画面要点"，仅保留 核心结论 + 画面要点。

## 格式铁律

1. **武将数量/星级**：写「50多个 5星武将」；**禁止「50+ 5星」**（+与星级相邻易误读）。
2. **cost 与星级严格分离**：报告正文**不写 cost**（需要时查库）；**禁止 `cost 3×2` 连写**（×N 无画面依据，cost 数字与星级数字易混淆）。
3. **武将库枚举**：格式 `阵营 武将名 cost N`（仅 JSON 内部可带 cost），不编造 ×N。
4. **日常武将表述**：`阵营-武将名-星级-兵种`（魏-曹操-5星-骑），唯一锁定；红度/统率/攻击距离不写入。

## 索引块

- 关键词：**从核心结论提取**（体系黑话+核心武将），限 12 个内；**严禁全并 glossary**。
- 核心武将（版本标签）：`阵营-兵种-N星`，只出现在索引块 + 阵容表格两处；正文 prose 不重复版本标签。
- 报告生成日期：唯一时间戳，**禁时效性警告语**（"可能已过时"等一律不写）。
- 位置词（大营/中军/前锋）严禁并入武将名。

## JSON 结构规范

- glossary 只收真「黑话/术语」（玩家行话/体系名/机制名），**不收画面字段**（红度/Lv/ID/标识/星级）；**疑问标注（"(疑似X)"）严禁进 glossary**，确认不了的进 limitations。
- entities.skills/gears 的 in_whitelist 必须与最终核验一致（确认后更新 True，不留矛盾标注）。
- corrections：只保留真纠错（音频严重失真且影响理解），"完全匹配/FOUND"类废话确认删除。
- summary.visual_only：只收核心要点（≤4 条），详细画面细节让位 timeline（避免与 timeline 重复）。
- **画面分类表述必须可直接溯源**：未经同帧筛选 UI / 星标 / 自带战法锚定，不得写“四星库、女将库、某阵营筛选、全为某星级”等集合性结论；改写为“可见武将”“画面显示的卡牌列表”，并保留无法确认项。
- **时间戳不拼接**：一条 `visual_only` 或 `timeline.desc` 只能描述其标注时间范围内的内容；跨帧汇总必须注明范围，且不得把不同帧的名单、筛选状态或星级混为同一画面事实。
- summary.key_points：核心结论（方法论/推荐/启示），渲染器在「一·核心结论」渲染。
- summary.one_line：原散文摘要，**2026-08-22 起不再渲染**（与核心结论重复，AI 阅读无增量）；仅作为关键词提取的隐藏文本源（extract_keywords 行 189 仍读它），不出报告。

## 冗余红线

- 散文摘要(one_line) 已从报告删除（2026-08-22）；"一、内容摘要" 改名「一、核心结论与画面要点」，禁止再渲染 one_line。
- visual_only 与 timeline 重复 = 冗余（画面要点只收 ≤4 条核心，细节让位时间线）。
- 同一方法论/结论不得在 ai_inference 内重复 3 次（如 5 步法）。
- 已解决疑点不得留在 limitations（会误导 AI）。

## 冗余红线补充（2026-08-22 用户反馈：配将型内容）

- **称呼作者一律用「作者」，禁用「UP主」**（含「UP 主」空格写法）。报告与 JSON 中所有指称视频发布者之处统一为「作者」。
- **配将型内容只保留四类信息**：①武将信息 ②账号资源情况 ③配将思路 ④配将结果。其余一律冗余：
  - 删除**作者个人 ID / 粉丝 ID / 昵称**（如「北冥」「止戈丨青仙」「长史」「真秋色浓」「北斗丨疯踏」）——只保留泛称「作者」「粉丝」「粉丝账号」。
  - 删除**账号养成进度叙述**（如「按月卡从 0 养号」「月卡从 0 养号」「月卡零氪号」）。账号「画像」只留结果态（武将少/战法残缺/没有宝物/缺某核心武将或战法），不写养成路径。
  - 好友列表、聊天界面 ID、同盟名、地图 UI、要塞/土地等纯界面元素——不写。
- **画面要点（timeline.desc / summary.visual_only）只含真正要点**：
  - 剔除聊天 UI、好友列表、无关屏幕内容、作者/粉丝个人 ID。
  - 每帧描述聚焦「该帧与配将相关的核心信息」（阵容/武将/战法/宝物/账号资源/作者点评），无相关信息则精简或省略。
  - 例：原「00:04–00:07 聊天界面 + 右侧地图 split screen：UP主聊天ID「长史」+ 好友列表（…）」→ 仅保留「作者主张按账号武将池定制」。
  - 例：原「UP主「北冥」按月卡从 0 养号的粉丝「真秋色浓」账号情况」→ 「作者根据粉丝的账号情况」。
- 上述规则同样适用于 corrections / limitations / ai_inference / sources 等所有字段（凡出现作者/粉丝 ID、养号进度、UP主 措辞，一律清理）。
