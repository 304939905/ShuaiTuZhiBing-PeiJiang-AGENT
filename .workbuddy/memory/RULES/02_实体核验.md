# 规则 02：实体核验（白名单 / 误读映射 / 证据链）

> 权威来源：核验基准使用说明.md（2026-08-21 固化）+ 用户规则迭代

## 统一核验基准：`资料库/official_merged_whitelist.json`（五类）

| 键 | 数量 | 说明 |
|---|---|---|
| `heroes` | 428 | 武将名 |
| `skills` | 1135 | 战法（ext∪full∪skill_db∪methodName∪jineng_list∪supplement 并集，避免 ext 漏报） |
| `gears` | 115 | 宝物名 |
| `forge_traits` | 42 | 宝物锻造词条池全集 |
| `unit_traits` | 24 | 兵种词条（CSV 19 + 口述 5） |

## 使用规则

1. **武将名** → 查 `heroes`
2. **战法名** → 查 `skills`（自带战法再交叉 hero_extra methodName 确认归属武将）
3. **宝物名** → 查 `gears`；宝物词条 → 查 `forge_traits` 且须 ∈ 对应宝物 forge 池（gear_forge_pool.json）
4. **兵种词条**（unit_traits）→ 查 `unit_traits`；同名词条（灵动/强击）按位置判断：绿框(宝物卡标签)查 forge_traits、蓝框(兵种栏)查 unit_traits
5. 本地查不到 → 标「官方库无此名」，WebFetch 官网核验后再定
6. ⚠️ **「库无」主张的核验铁律（2026-08-22 事故后新增）**：凡在 limitations / sources / 正文断言某名"官方库无此名 / 未收录 / NOT FOUND / 查无"，**必须用 `official_merged_whitelist.json` 的扁平列表**（`name in merged["skills"]` / `merged["gears"]` / `merged["heroes"]`）判定，**严禁**对原始 dict 文件（`official_jineng_names_ext.json`/`official_skill_db.json`/`official_gear_names.json`/`gear_id.json` 等）做 `name in raw_dict`——这些文件是 `{count,names}` / `{skills,...}` 结构，dict 键名成员判定**永远为 False**，会把所有真实存在的名字误判为"查无"（第十三期已因此把 大柯斧/百战无怯/久战熟谋 错判查无，已修正）。合并白名单已并集最全，是"查无"主张的唯一权威基准。
6. **画面字不在白名单** → 先查 `资料库/ocr_misread_map.json`：
   - 命中（如 抚危→扰后、亢戎→元戎、太势→大将）→ 结合证据链（武将自带战法/队伍名/官方库）确认后采纳，limitations 记录「画面字 X 经映射+证据链修正为 Y」
   - 未命中 → 标「OCR存疑」待人工核验
   - 维护：每次人工核验确认新误读对即追加（正确词条须已在白名单）

## 证据链铁律

- **武将自带战法以本地库为准**（hero_extra methodName），画面字与官方名形近标 OCR 存疑；证据链确定真名（队伍名+自带战法匹配）直接写真名。
- **官方库一律不补录**（2026-08-21 用户规则）：不确定项保留画面字面 + limitations 标注，须用户真人核验同意后才可补录。
- 来源优先级：官方接口 JSON ＞ 网易大神 ds.163.com ＞ 官网图鉴。

## 版本唯一锁定原则（2026-08-22 用户规则）

- 版本判定优先用**已确认的自带战法**；看不到自带战法时，若同帧已确认**武将名+星级+阵营+SP/XP/无标识**且在本地库唯一匹配，也可采用该官方版本。任何一项缺失、原帧不可回查或候选不唯一，直接“版本待核实”。
- 示例：5星+群+田丰 → 库中唯一版本（尽言直谏，群-骑），画面兵种看不清不影响确定。
- ⚠️ 孙权这类普通/XP 同名同阵营同星级卡，SP/XP 标识（或明确未见标识）是唯一性条件的一部分；不允许仅凭名字或资料库顺序取普通版。

### 姜维（蜀 5 星「列营守险」）专用兜底（2026-08-25 用户规则）

- 姜维的蜀弓、蜀步版本原画和自带战法「列营守险」相同，**不得**以原画或自带战法在两者之间单独定版。
- 如画面展示初始属性，按**初始攻城**判定：`19` = **蜀-步-5星**；本地资料库中的蜀弓对应初始攻城为 `9`。
- 未展示或看不清初始攻城时，写“版本待核实”；不得因队伍站位、兵种词条、战法搭配或资料库顺序猜弓/步。

### 卡面组合与属性消歧（2026-08-25 用户规则）

- 自带战法读不清时，不得把整张卡直接视为“无信息”。应逐项读取：**姓名、阵营、星级、兵种、武将卡 SP/XP/无标识、COST/有效距离（若可见）**；与本地资料库候选逐项比对，只有组合后唯一才锁定版本。
- 初始属性可作为消歧证据，但必须先在本地资料库列出候选的可重复差异，再按画面精确值匹配；不得以成长、加点后属性或模糊数值猜版本。姜维初始攻城规则见上节。
- **武将卡标识与战法卡标识必须分开。** 战法图标旁的 XP/SP/S2/A/S 等级或赛季标识，只说明该战法，绝不能当作武将的 XP/SP 标识；武将 XP/SP 只认武将卡本体的清晰标识。
- 原画可作为最后一层辅助比对，且只可对照官网武将详情页卡面。原画相同、画面模糊、未见官方对照图或仍有多个候选时，一律“版本待核实”。

## 觉醒标记「极」与标签体系分离（2026-08-23 固化）

- 卡面「极」字 = 武将觉醒状态标记（初始战法满级 + 消耗同星级卡开启第三战法格），**不是星级/品质体系的概念**。
- `version_label` 格式为「阵营-兵种-星级」（如 `汉-弓-4星`），**不得混入「极」**（如 `汉-弓-4星极` 为错误格式）。
- 觉醒状态信息已通过 timeline desc 画面描述记录（如「朱儁（汉，4 星极，Lv.40）」），标签去极不丢失信息。
- 参考：网易大神官方攻略——金色/红色「極」= 已觉醒标记，与版本无关。

## 阵营＋兵种队伍简称的近音字幕纠错（2026-08-25 用户规则）

- `晋步 / 吴弓 / 晋弓 / 魏骑 / 蜀骑` 等是“阵营＋兵种”的队伍简称，**不是武将名或独立实体**。
- 语音、硬字幕、OCR 常把简称误成同音/近音普通词；例如口述“小吴弓”可能被字幕写为“小蜈蚣”。不得按字幕字面把这种词写进术语、武将、战法或宝物字段。
- 纠正证据链：同一时间段的阵容画面能够确认阵营与兵种 → 可在正文写正确简称，并在审计/limitations 留“字幕近音误读”说明；仅有音频或字幕近音、没有对应画面证据 → 保留字面并标“队伍简称 OCR 存疑”，不得自行改正。
- 输出时优先写“晋阵营步兵队（简称‘晋步’）”等首次全称；后文可用简称。不要把“小/大/神/平民”等口语修饰词解释成版本、星级或固定体系。

### 队伍体系名 / 外号与武将版本隔离（2026-08-25 用户规则）

- 队伍体系名称、简称或外号可能沿用历史叫法、玩法叫法或作者口径，**不要求与当前队内每一名武将的阵营、兵种、版本逐字一致**；不能仅因名称与卡面信息表面不一致，就判定队名或武将信息错误。
- 队名只用于理解视频语境，**不能作为任何武将版本、阵营、兵种的正向或反向证据**。武将信息一律以该武将自身的卡面、自带战法，或可复核的初始属性证据为准。
- 若原视频使用的队名与已核实的武将卡面并存，正文保留原队名；需要说明时写“该称呼为原视频/作者的队伍叫法，非武将版本判定依据”，不得擅自改名或借队名推断武将。

## 常见实体坑（已发生）

- traits(宝物词条) 被误填 unit_traits 内容——traits 必须单独读宝物卡蓝色小标签，严禁抄 unit_traits。
- "稀世"是宝物品级字样，"极"是觉醒标记，**两者都不是词条/标签，禁止写入 traits 或 version_label**。
- 已确认实体（垒实迎击/火烧连营/徐氏匕首/游飘/大将/博浪 等）不得再标 NOT_FOUND/疑为——旧疑问标注必须随确认态更新。
